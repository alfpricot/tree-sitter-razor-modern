# tree-sitter-razor-modern architecture

This repository is a tree-sitter grammar for ASP.NET Core Razor markup (`.cshtml` and `.razor`). The grammar is written in JavaScript, the tree-sitter CLI generates a C parser from it, and Rust and Node bindings wrap that parser. It is a maintained fork of an upstream Razor grammar and extends the C# grammar, so code inside Razor blocks is parsed by `tree-sitter-c-sharp`'s own rules.

The main design choice is that the generated parser is committed. Consumers build from `src/parser.c` and never need the tree-sitter CLI, and CI fails when the committed files differ from what `grammar.js` generates.

## What tree-sitter-razor-modern is not

- It is not a Razor compiler or a C# analyzer. It produces a syntax tree and nothing else.
- It is not a standalone C# grammar. C# parsing comes from the `tree-sitter-c-sharp` dependency.

## Major components

### [grammar.js](grammar.js)

The grammar definition. It extends the C# grammar, adds the Razor nodes (expressions, code blocks, directives, control structures, comments, and HTML elements), and declares the external tokens the scanner produces.

### [src/](src)

The generated parser (`parser.c`, `grammar.json`, `node-types.json`), committed, and `scanner.c`, the hand-written external scanner for the tokens `grammar.js` cannot express as rules. Edit `grammar.js` and regenerate; never edit the generated files by hand.

### [queries/](queries)

`highlights.scm` and `injections.scm`. Both inherit the C# queries. The injection query hands HTML elements to the HTML grammar and comments to the comment grammar.

### [bindings/rust](bindings/rust)

The Rust crate. `lib.rs` exports `LANGUAGE`, `NODE_TYPES`, and the two query strings, and `build.rs` compiles `src/parser.c` and `src/scanner.c`.

### [bindings/node](bindings/node)

The Node addon: `binding.cc` (built through `binding.gyp`), `index.js`, type declarations in `index.d.ts`, and tests for the binding and the queries.

### [test/](test)

`corpus/` holds tree assertions per Razor construct, and `highlight/` holds highlight assertions. `check-examples.sh` parses every file in [examples/](examples) and fails on `ERROR`, `MISSING`, or zero-width nodes. `node-kinds.txt` is the committed snapshot of node kinds and field names, regenerated by `generate-node-kinds.mjs`.

### [tools/](tools)

Release-policy and package-content scripts that the release workflows call, with their own tests.

## External systems and data flow

- **tree-sitter-c-sharp** (a development dependency in `package.json`): `grammar.js` imports it to extend the C# rules.
- **crates.io**: the Rust crate is published from `Cargo.toml` by the release workflow.
- **npm and GitHub Packages**: the Node package is published to the public npm registry, and a copy scoped to the repository owner goes to GitHub Packages. Prebuilt native addons for Linux and Windows are built in the release workflow and shipped inside the tarballs.

A parse runs from a consumer's call into the binding (Rust or Node), through the generated parser and the external scanner, and returns a tree whose node kinds match `test/node-kinds.txt`.

## Build, test, release, and deploy

- **Pull requests and pushes to `dev` and `main`**: `verify.yml` (workflow `Verify`) regenerates the parser and fails on drift, checks the node-kind snapshot, lints and format-checks the JavaScript, runs the corpus, highlight, and example checks, builds and tests the Rust and Node bindings, validates the pull request title, scans for secrets, and lints the workflow files.
- **Release**: when a promotion lands on `main`, `gala-release.yml` runs gala (configured in `.gala.toml`), which bumps the version in `Cargo.toml`, `package.json`, and `tree-sitter.json` from Conventional Commits, refreshes `package-lock.json`, regenerates the parser (whose metadata embeds the `tree-sitter.json` version), updates `CHANGELOG.md`, commits and tags the release, pushes both over a deploy key, and fast-forwards `dev` to the release commit. The workflow then dispatches `release.yml` on the new tag; that workflow publishes the crate and the npm packages and creates the GitHub Release with a WASM build attached.
- **Maintenance**: `cache-cleanup.yml` clears stale caches on demand, and Dependabot updates dependencies against `dev`.
- This repository is a library, so nothing is deployed.
